    1. 프로그래밍 언어

    여러 측정값에서 사용할 수 있는 값만 골라 합계나 평균을 구한다고 하자. 사람에게는 ‘잘못된 값은 빼고 계산해 줘’라고 말할 수 있지만, 프로그램에는 어떤 값이 잘못된 것인지와 남은 값이 없을 때 무엇을 할지까지 적어야 한다. 프로그래밍 언어는 이런 처리 규칙을 컴퓨터가 실행할 수 있는 형태로 표현하는 언어다. 그 언어의 규칙에 맞춰 작성한 글을 소스 코드라고 부른다.

    코드를 읽을 때는 기호를 외우기 전에 자료와 흐름을 나누어 보면 좋다. 무엇을 저장할지는 자료형과 변수로, 값을 어떻게 계산할지는 연산자로, 언제 어떤 작업을 할지는 분기와 반복으로 표현한다. 자주 쓰는 작업은 함수로 묶고, 이미 구현된 기능은 라이브러리에서 가져온다. 언어가 바뀌어도 이 질문들은 남지만, 값을 저장하고 오류를 알리는 구체적인 규칙은 달라질 수 있다.

    C 예제는 GCC 13.3.0의 C17 모드, Python 예제는 CPython 3.11.15에서 각각 실행한 결과를 제시한다. 입력은 코드에 적은 측정값이다.

    2. 자료형과 변수

    값은 프로그램이 다루는 개별 자료다. 측정 횟수 3, 측정값 12.5, 기록 이름 ‘오전’이 모두 값이다. 자료형, 또는 타입은 그 값의 종류와 허용되는 연산을 정한다. 정수형은 개수처럼 소수 부분이 없는 수를, 실수형은 소수 부분을 포함한 수를 표현한다. 문자열은 글자들의 나열이고, 불리언은 참·거짓을 나타내는 종류다. 예를 들어 화면에 보이는 숫자 문자열과 계산할 정수는 다르므로, 입력한 글자를 정수로 해석하는 변환이 필요할 수 있다.

    변수는 프로그램에서 값을 다룰 때 붙이는 이름이다. 다만 그 이름과 저장 공간의 관계는 언어마다 다르다. C에서 int count = 3;이라고 쓰면 정수형 변수 count를 선언하고 첫 값을 넣는다. 첫 값을 정하는 것을 초기화라고 한다. Python의 count = 3은 이름을 정수 객체에 연결한다. 객체는 실행 중 값과 타입 등의 정보를 가지고 존재하는 대상을 뜻한다. Python에서는 같은 이름에 나중에 문자열을 연결할 수 있지만, C의 int 변수 자체가 문자열형으로 바뀌지는 않는다.

    이처럼 C는 선언한 타입을 바탕으로 실행 전에 여러 타입 규칙을 검사한다. Python은 실행 중 실제 값의 타입에 따라 연산 가능 여부를 판단한다. 흔히 이를 정적 타입과 동적 타입의 차이라고 설명한다. 동적 타입이라고 타입이 없는 것은 아니고, 정적 타입이라고 업무상 잘못된 숫자까지 모두 잡아 주는 것도 아니다. 수량을 음수로 받아도 되는지와 같은 조건은 프로그램이 별도로 표현해야 한다.

    자료형에는 표현 범위와 정밀도의 한계도 있다. C의 정수형은 정해진 범위를 가지므로 큰 입력을 더하거나 곱할 때 그 범위를 확인해야 한다. 소수 값을 다루는 부동소수점은 수를 유한한 자릿수로 근사하는 방식이어서 모든 십진 소수를 정확히 담지는 못한다. 개수인지, 근삿값인지, 정확한 금액인지에 따라 타입과 계산 규칙을 고르는 편이 안전하다. 아래 C 예제는 작은 정수만 사용하는 설명용 입력이다.

    Python의 숫자·문자열·대입 규칙은 공식 입문 문서에서 확인할 수 있다.[1]

    3. 연산과 제어 흐름

    연산자는 값에 어떤 처리를 할지 나타내는 기호나 단어다. 더하기 +, 곱하기 *는 산술 연산이고, 같은지 확인하는 ==, 이상인지 확인하는 >=는 비교 연산이다. 비교한 결과를 묶는 논리 연산도 있다. Python의 and는 두 조건이 함께 필요한 때, C의 &&는 이에 해당하는 논리 조건을 쓸 때 사용한다. 값을 넣는 =와 같은지 묻는 ==는 목적이 다르다.

    계산 순서는 연산자의 우선순위를 따르지만 뜻이 잘 보이도록 괄호를 사용할 수 있다. 나눗셈도 언어와 타입에 따라 다르다. C에서 정수끼리 나누면 결과도 정수이고 소수 부분을 0 방향으로 버린다. Python의 /는 정수끼리 사용해도 실수 결과를 만들고, //는 아래쪽 정수로 내림하는 나눗셈이다. 특히 음수에서 두 규칙을 같은 것으로 보면 안 된다. C의 나눗셈·반복·배열 매개변수와 표준 출력 규칙은 WG14의 공개 C 위원회 초안에서도 확인할 수 있다.[8]

    제어 흐름은 어느 명령을 어떤 순서로 실행할지를 뜻한다. 기본은 위에서 아래로 순서대로 수행하는 순차 실행이다. 조건에 따라 갈림길을 선택하는 분기에는 if를 사용한다. 같은 처리를 여러 자료에 적용하는 반복에는 for나 while을 사용한다. C의 for는 초기화·계속할 조건·다음 단계의 변경을 한곳에 적을 수 있고, Python의 for는 주어진 자료의 항목을 차례로 꺼내 처리한다.[2]

    측정 기록을 더하는 작업이라면 합계를 먼저 0으로 두고, 각 기록이 사용 가능할 때만 더한다. 다음 기록으로 넘어가는 과정이 반복이고, 사용 여부에 따라 더하거나 건너뛰는 과정이 분기다. 반복문에는 작업이 끝나는 조건도 있어야 한다. 끝 조건 없이 상태도 바뀌지 않는 while을 쓰면 계속 같은 작업을 할 수 있다.

    코드가 문법에 맞는다는 사실만으로 이 흐름이 문제를 올바르게 해결하는 것은 아니다. 사용 가능 조건을 거꾸로 쓰거나 누적 합계를 반복 안에서 매번 0으로 만들면 실행은 되어도 다른 결과를 만든다. 먼저 입력 조건과 원하는 결과를 말로 정하고, 그 규칙을 코드와 대조하는 습관이 중요하다.

    4. 함수와 사용자 정의 자료형

    같은 계산을 여러 곳에서 사용하려면 처리에 이름을 붙여 묶는 것이 편하다. 함수는 입력을 받아 정해진 작업을 수행하고 필요하면 결과를 돌려주는 코드 묶음이다. 함수를 부를 때 넘기는 실제 값을 인수, 함수 쪽에서 그 값을 받을 이름을 매개변수라고 한다. return은 함수의 실행을 끝내며 호출한 쪽으로 결과를 돌려준다. 결과를 반환하는 일과 화면에 출력하는 일은 다르다.

    함수의 입출력을 설명하려면 하나의 기록이 무엇인지도 정해야 한다. 측정값과 사용 가능 표시를 별개 목록으로 관리하면 서로 다른 순서로 바뀌어 짝이 어긋날 수 있다. C의 struct는 서로 관련된 항목을 하나의 구조체 타입으로 묶는다. 구조체 안의 각 항목을 멤버 또는 필드라고 부른다. 아래 struct Reading은 value와 valid를 묶은 사용자 정의 자료형이다. 타입 정의는 기록의 모양을 정하고, 그 타입의 변수는 실제 기록을 담는다.[3]

    C의 함수 프로토타입은 함수 이름과 반환 타입, 매개변수 타입을 선언하여 호출 방식을 알리는 문장이다. 아래의 int accepted_total(struct Reading readings[], int count);는 기록들을 받아 정수 합계를 돌려준다는 선언이며, 실제 계산 부분은 파일 아래의 함수 정의에 있다. 컴파일러는 선언을 보고 호출 인수의 개수와 타입 등을 검사할 수 있다.[4] 화면을 미리 만들어 보는 UI 프로토타입과는 다른 뜻이다.

    #include <stdio.h>
struct Reading { int value; int valid; };
int accepted_total(struct Reading readings[], int count);
int main(void) {
    struct Reading readings[] = {{12, 1}, {99, 0}, {18, 1}};
    printf("%d\n", accepted_total(readings, 3));
    return 0;
}
int accepted_total(struct Reading readings[], int count) {
    int total = 0;
    for (int i = 0; i < count; i++) {
        if (readings[i].valid) {
            total = total + readings[i].value;
        }
    }
    return total;
}

    중괄호로 둘러싼 부분은 한 묶음의 코드인 블록이다. readings[]는 기록들을 배열로 선언하고, readings[i]는 i번 기록을 읽는다. 배열 번호는 0부터 시작한다. .valid는 그 기록의 사용 가능 표시다. C의 조건식에서는 0을 거짓, 0이 아닌 값을 참으로 판단하므로 이 예제에서는 1인 기록만 더한다. i++는 다음 배열 번호로 한 칸 진행시킨다.

    함수 매개변수의 readings[] 표기는 호출 시 배열 첫 원소를 가리키는 포인터를 받는 형태로 조정된다. 포인터는 다른 값의 위치를 가리키는 값이다. 이 매개변수만으로 배열 길이를 알 수 없기 때문에 길이 count를 따로 받는다. 호출자는 실제 배열 범위를 넘지 않는 길이를 전달해야 한다. 타입 검사만으로 이 길이와 업무 의미까지 자동 확인되지는 않는다.

    #include <stdio.h>는 표준 입출력 함수의 선언을 사용할 수 있게 한다. printf의 %d는 정수를 표시하는 자리이고 \n은 줄바꿈이다. 합계 함수가 반환한 값을 printf가 화면으로 보낸다. main의 return 0은 프로그램의 정상 종료 상태를 나타내며 출력된 합계와는 별개의 값이다.

    이 코드를 gcc -std=c17 -Wall -Wextra -pedantic readings.c -o readings로 컴파일했을 때 종료값은 0, 경고 출력은 없었다. 생성된 프로그램을 실행한 표준 출력은 아래의 한 줄이었다. 사용 불가로 표시한 99는 합계에 들어가지 않았다.

    30

    구조체로 값을 묶었다고 그 자체로 변경 규칙이 강제되지는 않는다. 기록의 값을 누가 바꿀지, 어떤 동작을 제공할지는 더 넓은 설계 문제다. 객체지향 프로그래밍의 책임과 협력은 그 책임 분담을 다루는 별도 문서다.

    5. 유효 범위와 수명

    프로그램이 커지면 같은 이름을 어디까지 쓸 수 있는지가 중요해진다. 유효 범위는 코드에서 그 이름으로 대상을 가리킬 수 있는 구간이다. 수명은 실행 중 그 대상이 존재하는 기간이다. 코드를 읽는 범위와 실행 시간의 기간은 관련되지만 같은 개념은 아니다.

    앞의 C 함수에서 total은 함수 블록 안에서 쓰는 지역 변수다. 일반적인 자동 지역 변수는 그 블록의 실행에 맞춰 저장 공간이 마련되고 블록을 벗어나면 수명이 끝난다. 따라서 지역 변수의 위치를 반환해서 함수가 끝난 뒤 계속 사용하려 해서는 안 된다. 반면 블록 안에 static으로 선언한 지역 변수는 이름을 사용할 범위는 제한되어도 저장된 값은 다음 호출까지 유지된다.[5] 호출할 때마다 새로 계산해야 하는 합계에 이런 값을 무심코 사용하면 앞 호출의 결과가 섞일 수 있다.

    Python 함수의 지역 이름도 함수마다 별도로 관리되지만 이름이 사라지는 것과 객체가 없어지는 것은 구별해야 한다. 함수가 만든 리스트를 반환하고 호출자가 그 리스트를 계속 가리키면 함수가 끝난 뒤에도 사용할 수 있다. 이름을 값과 연결하는 Python 설명과 저장 공간의 수명을 중심으로 한 C 설명을 무조건 같은 규칙으로 옮기지 않는 것이 중요하다. 여러 함수가 함께 바꾸는 전역 상태는 추적이 어려워지므로, 필요한 값을 인수로 받고 결과를 반환하는 방식부터 익히면 흐름이 잘 보인다.

    6. 라이브러리와 입출력

    라이브러리는 다른 프로그램에서도 사용할 수 있도록 준비한 기능들의 모음이다. 평균을 구하거나 문자를 해석하는 흔한 기능을 매번 새로 작성하지 않게 해 준다. 언어와 함께 제공되는 표준 라이브러리와 별도로 선택하는 외부 라이브러리가 있다. API는 이런 기능을 부르는 이름·입력·결과 등 사용 약속이다. 함수의 이름만 아는 것보다 어떤 자료를 받고 빈 입력이나 오류 때 어떻게 반응하는지 아는 것이 중요하다.

    예를 들어 Python에서 정수 측정값의 산술평균이 필요하다면 표준 라이브러리의 statistics.mean 문서를 먼저 찾을 수 있다. 이 함수는 비어 있지 않은 자료의 합을 개수로 나눈 평균을 돌려주고, 빈 자료에는 StatisticsError를 발생시킨다.[6] 아래에서는 ‘음수는 사용 불가 표시’라는 별도 입력 규칙을 정하고, 사용 가능한 값이 없으면 계산 결과 없음인 None을 돌려주도록 감싼다. C 예제처럼 별도 valid 필드를 쓰는 방식과 달리, 이 방식은 음수도 유효한 측정인 분야에는 그대로 쓸 수 없다.

    from statistics import mean

def accepted_mean(values):
    accepted = []
    for value in values:
        if value >= 0:
            accepted.append(value)
    if not accepted:
        return None
    return mean(accepted)

print(accepted_mean([12, -1, 18]))
print(accepted_mean([-1]))

    from ... import ...는 모듈에서 사용할 이름을 가져오는 문장이고, 모듈은 Python 코드를 묶는 단위다. def는 함수를 정의하며, 들여쓰기가 함수·조건·반복의 묶음을 나타낸다. 빈 리스트를 거짓으로 판단하는 규칙을 이용해 if not accepted로 빈 입력을 확인했다. CPython 3.11.15에서의 출력은 다음과 같았다. 두 번째 출력은 측정 평균이 0이라는 뜻이 아니라 계산할 자료가 없다는 뜻이다.

    라이브러리를 고를 때는 먼저 필요한 동작과 데이터 규모를 정하고, 공식 문서에서 입력 타입·지원 버전·반환값·오류 규칙을 확인한다. 표준 기능으로 충분한지 살핀 뒤 외부 제품이 필요하다면 유지보수 상태, 라이선스, 의존 패키지와 배포 환경의 호환성도 비교한다. 선택 후에는 언어에 맞게 가져오거나 연결하고, 작은 정상 입력과 빈 입력으로 사용 약속을 확인한다.

    입출력은 프로그램 바깥에서 자료를 받거나 결과를 내보내는 작업이다. 키보드나 파일에서 받은 글자는 필요한 타입으로 변환하고 형식·범위를 검사한 뒤 계산에 넣는다. 계산 함수와 출력 함수를 나누면 화면 대신 파일에 저장할 때도 같은 계산을 재사용하기 쉽다. 이 글의 입력은 코드 안에 적은 값이고 출력은 표준 출력이다.

    7. 언어의 특성과 선택

    프로그래밍 언어를 분류하는 말은 서로 다른 기준을 섞기 쉽다. 절차적 방식은 값을 바꾸는 순서와 함수를 중심으로 처리 과정을 표현한다. 앞의 C 합계 함수가 이런 방식이다. 선언형 방식은 원하는 결과와 조건을 중심으로 표현하며, SQL 조회는 대표적인 사례다. 실행기가 구체적인 처리 계획을 선택하더라도 작성자는 결과가 뜻하는 바를 정확히 지정해야 한다.

    스크립트는 실행 환경이 읽어 수행하도록 작성한 프로그램으로, 반복 작업 자동화나 다른 기능을 연결할 때 자주 사용한다. Python은 이런 작업에 유용하면서 큰 프로그램을 구성하는 기능도 제공한다.[7] 스크립트라는 말과 절차적·객체지향이라는 말은 같은 분류 축이 아니므로 한 언어가 여러 특성을 가질 수 있다. 객체지향은 상태와 동작의 책임을 객체로 묶는 관점이다.

    컴파일과 해석도 언어 이름에 붙은 절대적인 양자택일은 아니다. 구현에 따라 중간 코드를 만들거나 실행 중 기계어로 변환하는 과정이 섞일 수 있다. 이 글의 C 코드는 GCC로 실행 파일을 만든 뒤 실행했고 Python 코드는 CPython으로 실행했다. 실행 속도는 언어 이름만으로 결정되지 않고 구현과 작업에 따라 달라진다.

    선택은 해결할 문제에서 시작한다. 기존 C 코드와 메모리 표현을 맞춰야 하는지, Python의 자료 처리 도구를 활용해 자동화를 빨리 구성해야 하는지, 저장된 자료의 조건별 조회가 중심인지에 따라 필요한 기능이 다르다. 성능을 개선할 때도 언어를 바꾸기 전에 반복 계산이나 불필요한 자료 복사가 있는지 확인할 수 있다. 앞 Python 예제는 사용할 값들을 별도 리스트에 모으므로 추가 공간이 든다. 원소를 순차적으로 전달하는 방식으로 바꿀 여지는 있지만, 동작과 입력 재사용 여부를 먼저 확인하고 효과는 별도로 측정해야 한다. 자료량에 따른 탐색·정렬의 선택은 자료구조와 알고리즘에서 이어진다.
