    1. 프로그래밍 언어와 실행

    ‘잘못된 측정값을 빼고 계산한다’는 요구를 받으면 무엇부터 적어야 할까? 어떤 값이 잘못됐는지, 합계와 평균 중 무엇을 구할지, 남은 값이 없으면 무엇을 돌려줄지를 정해야 한다. 프로그래밍 언어는 이러한 자료와 처리 규칙을 실행 가능한 형태로 적는 언어이고, 그 규칙에 맞춰 작성한 글이 소스 코드다. 문법은 기호를 쓸 수 있는 형태를 정하지만 업무상 정답까지 정해 주지는 않는다.

    코드를 읽는 핵심은 입력에서 결과까지 값의 변화를 추적하는 것이다. 값의 종류는 자료형으로, 값을 다룰 이름은 변수로, 계산은 연산자로 표현한다. 조건에 따라 갈라지는 분기와 여러 항목에 같은 일을 하는 반복을 합치면 처리 흐름이 된다. 함수는 그 흐름에 이름과 입출력 경계를 붙이고, 라이브러리는 이미 준비된 기능을 제공한다.

    소스 코드를 실제로 수행하는 과정은 언어 구현에 달려 있다. C 예제는 GCC의 C17 모드로 실행 파일을 만든 뒤 실행하고, Python 예제는 CPython 3.11.15로 실행한다. 컴파일은 코드를 다른 실행 형태로 변환하는 과정, 해석은 실행 환경이 코드의 동작을 수행하는 과정이다. 중간 코드 변환을 섞는 구현도 있어 언어를 두 종류로 영구히 나누는 기준은 아니다.

    2. 값과 처리 흐름

    계산 기호를 쓰기 전에 자료의 뜻을 정해야 한다. 측정값과 ‘사용 가능’ 표시는 서로 다른 자료다. 숫자 99를 보았다는 이유만으로 오류라고 판단하지 않고, 입력 계약이 무엇이라고 정했는지 확인한다.

    2.1 자료형과 변수

    자료형, 또는 타입은 값의 종류와 허용 연산을 정한다. 정수는 개수처럼 소수 부분 없는 값, 실수형은 소수 부분을 포함한 값, 문자열은 글자의 나열, 불리언은 참·거짓을 표현한다. 입력창의 글자 ‘12’는 계산할 정수 12와 같지 않다. 글자를 숫자로 변환하고 허용 범위까지 확인한 뒤 계산해야 한다.

    변수는 값을 다루는 이름이다. C의 int count = 3;은 정수형 변수를 선언하고 첫 값을 넣는 초기화를 한다. Python의 count = 3은 이름을 정수 객체에 연결한다. 객체는 실행 중 값·타입 등의 정보를 갖는 대상이다. Python 이름은 나중에 문자열 객체를 가리킬 수 있지만, C의 int 변수 자체가 문자열형으로 바뀌지는 않는다.[1]

    C는 선언한 타입에 따라 실행 전 여러 규칙을 검사하고, Python은 실행 중 실제 값의 타입에 따라 연산 가능 여부를 판단한다. 이를 정적·동적 타입의 차이로 설명한다. 동적 타입에도 타입은 있으며 정적 타입도 ‘음수 수량 금지’ 같은 업무 규칙을 저절로 보장하지는 않는다.

    C 정수형에는 표현 범위가 있어 큰 합계는 범위를 넘을 수 있다. 부동소수점은 유한한 자릿수로 수를 근사하므로 십진 소수를 모두 정확하게 표현하지 못한다. 개수·근삿값·정확한 금액 중 무엇을 다루는지에 따라 표현과 계산 규칙을 고른다. 아래 C 예제는 표현 범위 안의 작은 정수에 한정한다.

    2.2 연산·분기·반복

    연산자는 값에 수행할 일을 나타낸다. +와 *는 산술, ==와 >=는 비교다. 대입 =는 값을 연결하거나 저장하고, ==는 같은지 묻는다. Python의 and, C의 &&는 두 조건이 함께 필요한 논리식을 만든다. 우선순위가 헷갈리면 괄호로 의도를 분명히 한다.

    같은 나누기 기호도 언어와 타입을 봐야 한다. C의 정수 나눗셈은 소수 부분을 0 방향으로 버리므로 -7 / 3은 -2다. Python의 /는 실수 결과를 만들고 정수 피연산자의 //는 아래쪽 정수로 내려 -7 // 3이 -3이다. C 규칙의 공개 근거인 WG14 N1570은 C11 위원회 초안이며 C17 최종 표준 그 자체는 아니다.[2]

    제어 흐름은 명령을 수행하는 순서다. 차례대로 수행하는 순차 실행, 조건에 따라 선택하는 분기, 같은 처리를 되풀이하는 반복이 기본이다. if는 분기, for와 while은 반복을 표현한다. C의 for에는 시작값·계속할 조건·다음 단계 변경을 적고, Python의 for는 자료에서 항목을 차례로 받는다.[3]

    측정 합계의 초기화는 반복 전에 한 번 한다. 각 기록을 확인하고 사용할 수 있을 때만 더한 뒤 다음 기록으로 넘어간다. 매번 반복 안에서 합계를 0으로 만들면 앞 기록을 잃는다. 반복 조건이 끝나지 않거나 진행 상태가 바뀌지 않아도 잘못된 흐름이 된다. 문법 검사만으로는 이 의도를 확인하기 어려워 값의 변화를 따라 읽어야 한다.

    3. 함수와 데이터 묶음

    여러 화면에서 같은 계산을 한다면 매번 반복문을 복사할 필요가 없다. 계산을 한곳에 묶고 무엇을 받아 무엇을 돌려주는지 정하면 호출부의 목적도 분명해진다.

    3.1 함수·구조체·프로토타입

    함수는 입력을 받아 일을 수행하고 필요하면 결과를 돌려주는 코드 묶음이다. 호출자가 넘기는 실제 값은 인수, 함수에서 받을 이름은 매개변수다. return은 함수 실행을 끝내며 결과를 호출자에게 돌려준다. 반환은 화면에 출력하는 일과 다르다.

    측정값 목록과 사용 여부 목록을 따로 바꾸다 보면 짝이 어긋날 수 있다. 구조체는 관련 항목을 한 기록으로 묶는 C의 사용자 정의 자료형이다. 각 항목은 멤버 또는 필드다. struct Reading은 value와 valid가 함께 움직일 기록 모양을 정하고, 실제 변수는 그 기록을 담는다.[4]

    함수 프로토타입은 이름·반환 타입·매개변수 타입을 미리 알리는 선언이다. accepted_total 선언을 읽으면 기록들과 개수를 받고 정수 합계를 돌려준다는 것을 안다. 컴파일러는 호출 인수와 선언의 타입을 비교할 수 있지만, count가 실제 배열 길이 안인지까지 이 선언이 검사하지는 않는다.[5] 화면 시제품을 뜻하는 UI 프로토타입과는 다른 용어다.

    코드의 중괄호는 블록을 묶는다. readings[i]는 0부터 센 i번 기록, .valid는 그 기록의 필드다. C 조건에서는 0이 거짓, 0이 아닌 값이 참이므로 입력의 1 표시가 더하기를 허용한다. i++는 다음 번호로 진행한다. 배열 매개변수 readings[]는 원소 위치를 가리키는 포인터를 받는 형태로 조정되며, 길이는 별도 count로 전달한다. 호출자는 실제 범위를 넘지 않는 길이를 주어야 한다.

    #include <stdio.h>는 표준 입출력 함수 선언을 사용하게 한다. main은 이 프로그램의 시작 함수이고, printf는 결과를 표준 출력으로 보낸다. %d는 정수 자리, \n은 줄바꿈이다. main의 return 0은 정상 종료 상태이며 합계와는 별개다.

    #include <stdio.h>
struct Reading { int value; int valid; };
int accepted_total(struct Reading readings[], int count);
int main(void) {
    struct Reading readings[] = {{12, 1}, {99, 0}, {18, 1}};
    printf("%d\n", accepted_total(readings, 3));
    return 0;
}
int accepted_total(struct Reading readings[], int count) {
    int total = 0;
    for (int i = 0; i < count; i++) {
        if (readings[i].valid) {
            total = total + readings[i].value;
        }
    }
    return total;
}

    첫 기록은 valid가 1이라 total이 0에서 12로 바뀐다. 두 번째 99는 valid가 0이라 12를 유지한다. 마지막 18을 더하면 30이고, 다음 번호 3에서 반복 조건이 거짓이 되어 30을 반환한다. printf는 그 반환값을 표시한다. C17 모드의 gcc -std=c17 -Wall -Wextra -pedantic로 컴파일하고 실행한 출력이다.

    30

    이 입력은 숫자 자체가 아니라 별도 valid 필드로 사용 여부를 판단한다. 구조체는 짝을 묶을 뿐, 기록을 누가 바꾸어도 되는지까지 제한하지 않는다. 합계 계산의 계약과 상태 변경의 책임은 별도로 설계한다.

    3.2 유효 범위와 수명

    유효 범위는 코드에서 이름을 쓸 수 있는 구간이고, 수명은 실행 중 대상이 존재하는 기간이다. 앞 함수의 total은 함수 블록 안에서 사용하는 지역 변수이며 일반적인 자동 지역 변수로서 블록 실행이 끝나면 수명도 끝난다. 따라서 그 저장 위치를 반환해 함수 종료 뒤 계속 접근하면 안 된다.

    블록 안의 static 지역 변수는 이름의 범위가 좁아도 저장 기간은 프로그램 전체다. 다음 호출까지 값이 남으므로 호출마다 새 합계를 내는 용도에 무심코 쓰면 이전 합계가 섞인다.[6] 이름을 어디서 볼 수 있는가와 값이 얼마나 오래 남는가를 나눠 묻는 이유다.

    Python에서는 함수의 지역 이름이 사라져도 반환한 리스트를 호출자가 계속 참조하면 그 객체를 사용할 수 있다. C의 자동 저장 기간을 Python 객체에 그대로 적용하지 않는다. 공유 전역 상태를 줄이고 인수와 반환으로 흐름을 연결하면 어느 호출이 어떤 값을 바꿨는지 추적하기 쉽다.

    4. 라이브러리와 입출력

    라이브러리는 여러 프로그램이 쓰도록 준비한 기능 모음이다. 표준 라이브러리는 언어 실행 환경과 함께 제공되고 외부 라이브러리는 따로 선택한다. API는 호출 이름·입력·반환·오류의 약속이다. 함수를 찾는 것만큼 그 약속을 확인하는 일이 중요하다.

    4.1 API 계약과 빈 입력

    Python statistics.mean은 산술평균을 계산하지만 빈 자료에는 StatisticsError를 낸다.[7] 아래 함수는 ‘음수는 사용 불가 표시’라는 입력 계약으로 값을 먼저 거르고, 남은 값이 없으면 결과 없음인 None을 돌려준다. 앞 C 코드의 99는 별도 valid 때문에 제외됐지만 여기의 -1은 값 자체가 표시다. 같은 문제를 언어만 바꿔 옮긴 코드가 아니며, 음수도 유효한 측정인 분야에는 이 계약을 그대로 적용할 수 없다.

    from ... import ...는 코드 묶음인 모듈에서 이름을 가져오고, def는 함수를 정의한다. 들여쓰기는 함수·반복·조건의 범위를 정한다. append는 목록 끝에 추가하며, 빈 리스트가 거짓으로 평가되므로 if not accepted로 남은 자료가 없는지 확인한다.

    from statistics import mean

def accepted_mean(values):
    accepted = []
    for value in values:
        if value >= 0:
            accepted.append(value)
    if not accepted:
        return None
    return mean(accepted)

print(accepted_mean([12, -1, 18]))
print(accepted_mean([-1]))
    15
None

    CPython 3.11.15의 첫 호출은 12와 18만 모아 합 30을 개수 2로 나눈 15를 반환했다. 두 번째 호출은 -1을 제외한 뒤 빈 목록이 되어 mean을 부르지 않고 None을 반환했다. 0 평균과 계산할 값 없음은 다른 결과이므로 호출자도 둘을 구별해야 한다.

    4.2 입력에서 결과까지

    입출력은 프로그램 밖의 자료를 받거나 결과를 보내는 작업이다. 파일과 키보드에서 받은 글자는 형식·타입·범위를 검사한 뒤 계산에 넣는다. 예제는 코드에 적은 값과 표준 출력을 사용했지만 계산 함수가 출력 장치를 직접 다루지 않아 화면 대신 파일을 쓰더라도 같은 계산을 활용할 수 있다.

    검토 순서는 입력 의미, 선택 조건, 반복 종료, 반환값이다. C에서는 사용 표시가 참인 기록만 누적했고 Python에서는 쓸 값을 모은 뒤 빈 목록을 먼저 처리했다. 정상 입력 하나를 통과한 것으로 끝내지 않고 모두 제외되는 경우와 빈 입력도 시험해야 한다. 작은 프로그램에서도 계약과 관측 결과를 연결하는 연습이 문법 암기보다 중요하다.

    5. 언어의 특성과 선택

    절차적 방식은 값을 바꾸는 순서와 함수를 중심으로 표현한다. 앞의 C 합계가 그 예다. 선언형 방식은 원하는 결과와 조건을 중심으로 표현하며 SQL 조회가 대표적이다. 실행기가 처리 계획을 정해도 작성자가 결과의 의미를 명확히 해야 한다. 객체지향은 상태와 행동의 책임을 객체로 묶는 관점이다.

    스크립트는 실행 환경이 읽어 수행하게 작성한 프로그램으로 자동화나 기능 연결에 자주 쓰인다. Python은 이런 작업뿐 아니라 큰 프로그램을 구성할 기능도 제공한다.[8] 스크립트라는 말은 절차적·객체지향과 같은 분류 축이 아니어서 한 언어에 여러 특성이 함께 있을 수 있다.

    선택은 기존 코드와의 호환, 필요한 라이브러리, 메모리 표현, 배포 조건에서 시작한다. 외부 라이브러리는 입력·오류·지원 버전뿐 아니라 라이선스와 유지보수, 의존 패키지도 확인한다. 실행 속도는 언어 이름만으로 결정되지 않는다. Python 평균 예제도 별도 리스트에 값을 모으는 공간 비용이 있다. 자료를 순차 전달하도록 바꾸려면 재사용 여부와 동작을 확인하고 성능 개선은 따로 측정해야 한다.
